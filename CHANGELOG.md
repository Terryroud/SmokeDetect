# Changelog

## [Unreleased]

### Added
- Новый эндпоинт `/stream/detect-smoking` для детекции курения на загруженных фото
  - Принимает изображения через `multipart/form-data`
  - Возвращает JSON с результатом анализа (Yes/No)
  - Поддерживает форматы JPEG и PNG
- **Новый эндпоинт `/stream/open-stream-url` для обработки видео потоков по URL**
  - Сервер самостоятельно подключается к видео потоку (HLS, RTSP, HTTP)
  - Обрабатывает видео в реальном времени с детекцией курения
  - Настраиваемый интервал детекции (по умолчанию 5 секунд)
  - Результаты передаются через WebSocket всем подключенным клиентам
  - Видео автоматически сохраняется в MP4 файл
  - Доступен просмотр через MJPEG поток в реальном времени
  - Поддержка HLS (.m3u8), RTSP, HTTP/HTTPS потоков
- Добавлены Pydantic модели:
  - `SmokingDetectionResponse` для ответа детекции курения
  - `StreamUrlRequest` для запроса на открытие стрима по URL
  - `StreamUrlResponse` для ответа при открытии стрима по URL
- Интеграция с OpenAI API через OpenRouter для анализа изображений
- Фоновая задача `process_video_stream_from_url` для асинхронной обработки видео потоков
- Добавлены примеры использования в README.md для Python, cURL и JavaScript
- Тестовый скрипт `test_detect.py` для проверки эндпоинта

### Changed
- Упрощена модель ответа `SmokingDetectionResponse` - убрано поле `message`
- Улучшена нормализация ответа от AI модели:
  - Если в ответе содержится "yes" (в любом регистре) → возвращается "Yes"
  - Если в ответе содержится "no" (в любом регистре) → возвращается "No"
  - Применяется как для HTTP эндпоинта `/detect-smoking`, так и для WebSocket стриминга
- **Оптимизирована детекция курения для URL стримов:**
  - `/stream/video/{id}` - просто MJPEG трансляция БЕЗ детекции (экономит ресурсы)
  - Детекция запускается ТОЛЬКО при подключении к WebSocket
  - AI модель вызывается только когда есть активные подписчики
  - Это значительно снижает нагрузку на AI API
- **КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ: Полностью асинхронная детекция без блокировки видео**
  - Номер кадра теперь захватывается в момент запуска детекции (не в момент завершения)
  - Кодирование изображения (PNG + base64) перенесено в `asyncio.to_thread` - не блокирует event loop
  - Используется `frame.copy()` для предотвращения race conditions
  - Параметры (frame_number, timestamp, frame_data) передаются как аргументы функции
  - Это гарантирует соответствие между логами "🔍 Запуск" и "✅ Результат"
  - Видео не отстает при запуске детекции
- Обновлен README.md с описанием нового функционала
- Добавлены зависимости в requirements.txt:
  - `openai` - для работы с AI моделью
  - `python-multipart` - для обработки загрузки файлов
  - `requests` - для HTTP запросов и парсинга веб-страниц

### Technical Details
- Используется модель `nvidia/nemotron-nano-12b-v2-vl:free` через OpenRouter
- Изображения конвертируются в base64 перед отправкой в API
- Обработка ошибок с информативными сообщениями
- Автоматическое определение формата изображения через OpenCV
- Умная нормализация ответа с проверкой вхождения подстрок
- **Полностью асинхронная архитектура детекции:**
  - Детекция выполняется через `asyncio.create_task` (fire-and-forget pattern)
  - Кодирование кадров (cv2.imencode + base64) через `asyncio.to_thread` - полностью неблокирующее
  - AI детекция выполняется через `asyncio.to_thread` для избежания блокировки event loop
  - Номера кадров фиксируются до запуска фоновой задачи
  - Используется `frame.copy()` для безопасности при многопоточности
  - Минимальная задержка в основном цикле (1ms) для плавности видео
  - Видеопоток работает с максимальной скоростью независимо от детекции
- OpenCV используется для чтения HLS/RTSP/HTTP потоков через `cv2.VideoCapture`
- **Автоматическое извлечение HLS URL из веб-страниц** - функция `extract_hls_url_from_page`
  - Парсинг HTML для поиска .m3u8 ссылок
  - Поддержка blob: URL путем извлечения реального HLS адреса
  - Автоматическая конвертация относительных URL в абсолютные
- Улучшенная диагностика ошибок при подключении к потокам
